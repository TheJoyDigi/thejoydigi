**Alex:** Welcome to Anthropic Blogcast. Today we are looking at a research post from Anthropic called The Components of Agent Memory, published on November sixth, about a deceptively simple problem, which is how an agent decides what is worth remembering before it knows what will matter later.

**Jordan:** The post opens with the philosopher Soren Kierkegaard, who wrote that life can only be understood backward, but it must be lived forward, and Anthropic says designing memory for AI agents runs into exactly the same bind.

**Alex:** First, what they mean by agent memory, because they define it narrowly. It is knowledge that Claude gains from experience, including interactions with users and tasks it has been assigned, and retains between sessions, saved as context it can read later.

**Jordan:** And they are careful about what it is not. It is not a change to the model weights set during training, not in context learning inside a single conversation, and not compaction, where summaries replace older turns so Claude can keep working in a new context window.

**Alex:** The human brain is their model. The hippocampus captures experiences in the moment, but only some are consolidated into long term knowledge, much of it offline, while we sleep, as the brain replays experiences and distills them into the neocortex.

**Jordan:** Anthropic gives agents a similar division of labor. In session, Claude can tag salient events or write notes to a memory store. Then, in idle time, a process they call dreaming reflects on those logs, fixes mistakes, and reorganizes the notes.

**Alex:** But writing in the moment has a problem. Claude must judge what is salient before it knows what is coming next. The post puts it beautifully. Memory is, occasionally, a prediction. Writing down a rule predicts the pattern will matter again, and writing down a verified fact predicts a future session will rely on it without double checking it. Over model generations, Claude has gotten much better at those predictions.

**Jordan:** They show that with Continual Learning Bench, version one point zero, which measures memory use on long horizon tasks. One task asks Claude to answer questions by looking up a database. After each answer it learns the correct solution, and can write a memory to help next time.

**Alex:** The setup rewards a learning loop. Get a question wrong, record the failure, form theories, test them, and turn what you learn into a rule. Sonnet four point six only generated theories, leaving scattered files of untested guesses. Opus four point seven consolidated its notes into one document, marking which facts were checked and which were not.

**Jordan:** Sonnet five marked each answer confirmed once graded, and corrected it when wrong. Opus five was the first to fully close the loop, with a rule, how it knew the rule was true, and warnings about traps. Opus five point five and Sonnet five point five closed the loop too.

**Alex:** The second evaluation is about judgment. They had Claude play Pokemon Red, giving each model a memory folder to read and write while it played, then compared Sonnet three point seven and Fable five at about ten thousand steps in.

**Jordan:** Sonnet three point seven assumed everything might matter, and wrote indiscriminately, often a separate file for each battle, each item, and each character it met. In total it wrote four hundred thirteen memory files across two hundred twenty five folders, and earned one badge. Fable five wrote nine files in two folders, plus a single top level file called global dot md, and earned four badges.

**Alex:** The hoarding hurt because the game state changes constantly, so that detailed record kept going out of date, and Claude spent more time combing through its memories than playing. At one point, over seventeen steps, it created six files, deleted nine others, and took no actions in the game itself.

**Jordan:** Fable five saved only what the game did not tell it. Money and map position can be read off the screen every turn, so storing them is redundant. Strategy, plans, and tested rules exist only if Claude works them out, and disappear unless it writes them down. Its global file was a dashboard with the current goal, a plan for the gyms, and its own rules for memory. After seven Poke Balls in a row failed to catch a Magikarp, it noted to vary the timing after three failures, and the catch landed right after. Opus five point five kept a similarly small folder and beat the game.

**Alex:** So what happens when you steer this? It helps to tell Claude what memory is for, but not how to use it. Simply saying a folder was available noticeably helped Opus four point seven and Opus five. But a rule to record only failures made both lose much of the boost. Freedom to judge salience beat fixed rules.

**Jordan:** Steering helped older models most. Sonnet four point six often did not read its memory or test its theories. Prompting it to do both nearly doubled its score. Sonnet five does that unprompted, reading memory nine out of ten times, while Sonnet four point six managed less than half.

**Alex:** Which brings us back to dreaming, because even good judgment in the moment leaves a problem. A note that is wrong from the start, or drifts as the environment changes, can be read and trusted in a later session. Dreaming lets Claude test its notes against the original transcripts.

**Jordan:** They show it at Mount Moon in Pokemon, a cave with a one way ledge near the entrance that drops the player back to the route they came from. Claude used the PokeCenter there as a landmark, wrote down incorrectly that it was on the east side, and marked Mount Moon as done when it was not.

**Alex:** When they ran dreaming on that folder, Claude checked the note against the transcript, caught the error, and rewrote it. With the corrected note, it went straight back in and eventually reached Cerulean City. With the uncorrected note, it dropped back onto that route three times, seemed to give up, and never reached Cerulean City at all.

**Jordan:** Dreaming can also build new representations, like a wiki of linked pages Claude maintains, a map of its own memory. They tested that on documents from Stainless, a company Anthropic acquired in May, about three hundred fifty thousand files and four hundred twenty million tokens, with twenty five questions.

**Alex:** Over one hundred twenty eight dreaming sessions, Opus five agents explored the files, wrote and corrected linked wiki pages, and checked claims against the sources. As dreaming scaled from two sessions to one hundred twenty eight, wiki only performance grew from thirteen percent to forty eight percent of the graded criteria. The wiki helped most alongside search, rising from fifty four percent to sixty one percent, versus fifty three percent for search alone, and using both saved about twenty thousand tokens per question.

**Jordan:** On a legal benchmark built around a merger, Claude scored eighty seven percent consulting the wiki, versus seventy three percent with search alone, on questions needing several documents plus judgment or math. But a wiki is not always useful. On one task the answers sat in a single searchable document, and the wiki added nothing. On another, it grew larger than the documents themselves, like the Borges mapmakers whose map was as large as the empire. A representation that abstracts nothing is just a second copy.

**Alex:** Dreaming can also promote key notes to the top of the hierarchy, so the harness loads them into context at the start of every session. That layer must stay small, because a wrong note loaded everywhere does damage everywhere. In Claude Code, auto memory loads only the first two hundred lines, or twenty five kilobytes, of its main file, as an index to the rest.

**Jordan:** Dreaming can also be focused on a goal. In one legal task, agents writing contract terms into a shared table overwrote each other, and the brief included only forty one of fifty seven facts, or seventy two percent. After Claude reflected and rewrote its own instructions, each contract got its own page quoting the terms word for word, and the next brief met one hundred percent of the criteria. Dreaming also fills gaps, repointing nine links to a missing wiki page and adding three new pages, including an index.

**Alex:** The post closes with open questions. Should Claude create memory in the moment, where logging pulls attention from the task, or in the background, where results are not immediately available? How do you keep memory current without impractical compute checking all of it? And should search be the foundation, with wikis on top, knowing they can accumulate errors?

**Jordan:** The through line for me is that memory is not storage. It is judgment, exercised twice, once in the moment, when Claude predicts what the future will need, and once offline, when dreaming looks backward and corrects the record. Four hundred thirteen files earned one badge. Nine files earned four. What you choose to forget is part of what makes the memory worth having.
